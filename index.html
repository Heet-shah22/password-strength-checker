Section 10.1: Entropy vs Heuristic Score

Why theoretical mathematics diverge from practical human passwords

📐

Theoretical Entropy

  • Assumes characters are chosen uniformly at random.
  • Gives full credit for each character regardless of human patterns.
  • Overestimates security of passwords like Password@123.
  • Cannot detect common dictionary words or predictable years.
🛡️

Project Heuristic Score

  • Deducts severe penalties (-4) for common word blocklists.
  • Identifies repeated triples (aaa) and sequential walks (123456, qwerty).
  • Provides actionable, educational feedback to guide users.
  • Aligns with NIST SP 800-63B modern guidance.

Section 14: Practical Guidance from Project Report

01
Prioritize Length over Forced Complexity

NIST SP 800-63B emphasizes that 16+ character passphrases resist brute-force far better than 8-character passwords with forced special characters.

02
Screen Against Common Blocklists

Systems should reject commonly leaked words (e.g. password, 123456, admin) immediately at registration.

03
Use Dedicated Password Managers

Human memory cannot securely maintain 100+ unique 16-character passwords. Password managers generate and store unique secrets across all accounts.

04
Mandate Multi-Factor Authentication (MFA)

A password strength checker is only one defensive layer. True defense in depth requires MFA (TOTP, WebAuthn/FIDO2) to prevent credential stuffing.

2. Problem Statement, Aim & Objectives (Section 2.1 – 2.4) ▼

Problem Statement: A common weakness in password creation is the assumption that a password is strong simply because it contains uppercase letters, numbers, and a symbol. A construction such as Password@123 satisfies several superficial complexity rules while remaining predictable.

Objectives: Analyze length, check character diversity, identify weak patterns, screen common passwords, calculate heuristic score, classify into 5 levels, provide recommendations, and promote security awareness.

3. Password Entropy vs Heuristic Scoring (Section 3.3 & 10.1) ▼

Entropy is a theoretical measure of uncertainty: H = L × log₂(N). If a password has length L over character pool N, idealized search space is NL.

Entropy vs Heuristic Score: Human-created passwords do not follow uniform-random models. Theoretical entropy vastly overestimates passwords like Password@123 (~78.8 bits), whereas a heuristic engine recognizes the predictable root word and suffix pattern.

9. Complete Python Source Code Listing (Section 9) ▼

The authentic Python implementation is saved at password_checker.py:

import re

COMMON_PASSWORDS = {
    "password", "password123", "123456", "12345678",
    "qwerty", "admin", "admin123", "letmein", "welcome",
    "welcome123", "iloveyou"
}

SEQUENCES = [
    "123456", "654321", "abcdef", "fedcba",
    "qwerty", "asdfgh"
]

def has_lowercase(password): return re.search(r"[a-z]", password) is not None
def has_uppercase(password): return re.search(r"[A-Z]", password) is not None
def has_digit(password): return re.search(r"\d", password) is not None
def has_special(password): return re.search(r"[^A-Za-z0-9]", password) is not None
def has_repetition(password): return re.search(r"(.)\1\1", password) is not None
def has_sequence(password):
    value = password.lower()
    return any(seq in value for seq in SEQUENCES)
def is_common(password): return password.lower() in COMMON_PASSWORDS

13. Advantages & Limitations of Heuristic Scoring (Section 13) ▼

Advantages (Section 13.1):

  • Easy to understand and explain during academic presentation.
  • Immediate preventive feedback without storing or exposing secrets.
  • Local execution with lightweight computational requirements.
  • Promotes security awareness and educates users on patterns.

Limitations (Section 13.2):

  • Heuristic rule score cannot perfectly model real-world attack power.
  • Small blocklists do not cover all 10+ billion leaked passwords.
  • Does not replace MFA, salted Argon2/bcrypt hashing, or rate limiting.
14. Security Best Practices (Section 14) ▼
  • Use long passwords/passphrases: Longer secrets create an exponentially larger search space.
  • Avoid password reuse: A separate password limits the impact of a breach at one service.
  • Avoid predictable personal info: Names, dates, phone numbers, and organizations may be discoverable.
  • Use a password manager: Managers generate and store unique secrets across all accounts.
  • Enable MFA: Multi-factor authentication adds an indispensable layer of defense in depth.
15 & 16. Future Scope & Conclusion (Section 15 & 16) ▼

Future Scope: Integration with breached databases using k-Anonymity privacy-preserving APIs (e.g. HaveIBeenPwned), machine-learning password analysis, and browser extensions for password creation forms.

Conclusion: The project demonstrates that length, uniqueness, and resistance to predictable patterns are vastly more meaningful than superficial character diversity alone.
